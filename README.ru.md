# codex-progress-panel

[English](README.md) | [Русский](README.ru.md)

Компактная панель прогресса для OpenAI Codex. Показывает, чем занят агент, что уже готово и что осталось, а также работу параллельных агентов и изменения требований к задаче.

![Панель прогресса на английском](docs/images/progress-panel-en.png)

Текущий компонент панели с демонстрационными данными на английском. Этот пример не подтверждает встроенное отображение или размещение в Codex.

## Возможности

- **Этапы задачи:** ожидающая, текущая, завершённая и заблокированная работа.
- **Параллельные агенты:** короткие сводки агентов под соответствующим этапом.
- **Изменение плана:** та же панель при уточнении требований; подтверждённый прогресс и история снятых этапов сохраняются.
- **Локальное хранение:** состояние запуска сохраняется после перезапуска сервера.
- **Итоговые снимки:** успешная финализация фиксирует историю запуска.
- **Актуальность:** время последнего подтверждённого обновления и отметка об устаревших данных через две минуты без обновлений.
- **Локальная работа:** без телеметрии, сетевого порта, внешних ресурсов и фонового демона.

Панель показывает прогресс, который сообщил агент. Она не проверяет правильность кода самостоятельно.

## Установка полного плагина

Установите полный плагин со skill, MCP-сервером и UI-интеграцией напрямую с GitHub:

```sh
codex plugin marketplace add Karikatun/codex-progress-panel
codex plugin add codex-progress-panel@codex-progress-panel --json
```

Начните новый чат и попросите: «Покажи этапы этой задачи в панели прогресса и обновляй их по мере работы».

Marketplace использует ветку `main`, которая может меняться. Чтобы выбрать конкретный Git ref, укажите `--ref`. Например, `codex plugin marketplace add Karikatun/codex-progress-panel --ref main` выбирает текущую ветку. Сейчас на GitHub нет версионных тегов или Releases.

12.10.2026 мы проверили установку с GitHub в Codex CLI `0.147.0` с новым изолированным каталогом `CODEX_HOME`. Ветка `main` указывала на проверенный commit `2915a86a1bf758cbf4b4664430025a81795fec50`; marketplace и установленный плагин совпали с проверенным исходным кодом. Проверка не изменила глобальную конфигурацию Codex. Встроенное отображение в приложении остаётся непроверенным; `0.147.0` — не минимальная версия. В [руководстве по установке](docs/installation.md) описаны локальный исходный код и отдельный сервер, обновление и удаление.

Для полного плагина нужны macOS или Linux, Python 3.9+ под именем `python3` в PATH и хост Codex с поддержкой плагинов, MCP `cwd` относительно плагина и MCP Apps UI.

Версия в исходных манифестах и публичном npm-пакете — `0.2.0`. На 2026-10-12 npm `latest` указывал на `0.2.0`. Источники указаны в [статусе распространения](docs/installation.md#distribution-status).

## Начало работы

Попросите Codex в новом чате:

> Покажи этапы этой задачи в панели прогресса и обновляй их по мере работы.

Во время работы можно уточнить задачу:

> Добавь проверку формата экспорта и обнови оставшиеся этапы.

Основной агент согласует план и сообщает прогресс. Панель не читает переписку автоматически и не управляет субагентами.

## Отдельный MCP-сервер

Используйте npm/npx, если нужен только сервер. Для него нужны Node.js 22+, npm/npx и Python 3.9+ на macOS или Linux.

```sh
npx -y codex-progress-panel@0.2.0 --help
```

Добавьте stdio-запись поддерживаемым хостом способом настройки MCP:

```json
{"mcpServers":{"progress":{"command":"npx","args":["-y","codex-progress-panel@0.2.0"]}}}
```

Это запускает отдельный MCP-сервер. Запись не устанавливает skill `progress-panel` и не активирует полный плагин. Сервер предоставляет HTML-ресурс, но для его отображения нужен хост MCP Apps. Подробнее — в [руководстве для отдельного сервера](docs/installation.md#use-the-npm-server).

## Как это работает

Полный плагин объединяет skill, stdio MCP-сервер на стандартной библиотеке Python и панель MCP Apps. Основной агент передаёт явные сводки прогресса; SQLite хранит каждый запуск с отдельной идентичностью и токенами доступа. Панель доступна только для чтения: она показывает сводки и запрашивает подтверждённые обновления. Успешный `finish_progress` фиксирует итоговый снимок; следующие запуски получают отдельные виджеты.

## Требования и ограничения

- Windows не поддерживается: защита локальных данных использует владельца и права POSIX.
- Хост управляет отображением, размещением и доступностью. Встроенное поведение `0.2.0` здесь остаётся неподтверждённым; протокольные тесты и имитация UI — отдельные доказательства.
- Завершённые этапы не доказывают успешную финализацию запуска. Stop или сбой до успешного завершения могут оставить снимок незавершённым.
- Устаревшие данные означают отсутствие свежего подтверждённого обновления. Это не доказывает сбой или остановку агента.
- Данные хранятся локально и приватно в `~/.codex-progress-panel/progress.sqlite3`. Автоматическая очистка по умолчанию выключена; история ограничена 128 запусками.

По умолчанию подписи интерфейса английские; можно включить русские. Сводки задачи сохраняют переданный язык. Язык, хранение и лимиты описаны в [конфигурации](docs/configuration.md), неподдерживаемые и отложенные возможности — в [ограничениях](docs/limitations.md).
